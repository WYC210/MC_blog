# Homecraft 物品纹理与材质细节分析

- 分析日期：2026-11-15
- 文档状态：首轮材质映射修复、分类增强与六类样板已实施，视觉审查待用户确认

## 1. 目标与工作边界

当前优先目标是改善世界中物品、建筑和地面的材质细节，让木材、石材、金属、布料等具有明确区别，而不是优先继续强化太阳、水面、辉光或整体调色。

参考对象：

- MC 写实材质方案，以 Stratum 的多通道材质路线作为技术参照，不作“唯一最真实”的排名。
- 本地页面：`homecraft-main/几猫国产3A大作_V1/几猫国产3A大作_V1.html`。
- 项目展示屋：`examples/terry-home/world/`，参考材质、物品比例和低成本反射实现。

分析阶段只新增本文档。用户随后授权按本文实施，首轮完成情况见第 10 节；本轮功能修改位于世界层及测试工具，没有新增引擎改动，也未回退用户既有内容。

用户最新确认：**只有普通模式受性能预算限制；超清模式已经有开启提醒，以画质优先，不受该预算限制。超清仍记录开销并检查功能正确性，不因超出普通模式预算判定失败。**

### 图片审查约定

后续修改遵循用户明确指定的流程：

1. 可以运行自动化检查、记录性能数据并生成截图。

## 2. 核心结论

现在的问题不只是贴图分辨率低，主要包括：

1. **材质身份丢失**：不少木头、石头、羊毛和绳索被映射为同一种 `paint`，仅靠颜色区分。
2. **结构细节不足**：已有颗粒和凹凸，但缺少与具体物品对应的木节、砖缝、织物组织、接缝等中尺度结构。
3. **物理参数分类过粗**：大理石、普通石头和瓷砖等共用基础参数，表面反射区别不足。
4. **增强存在条件和接入问题**：普通模式不安装材质增强，部分自发光关闭细节，地表类型传递存在不匹配。
5. **反射配套不足**：当前世界没有找到统一接入的物品环境反射，仅提高金属度不能补足这一环节。

推荐路线：**保留 MC 方块轮廓，先恢复正确材质，再建立分层表面结构，最后补充反射和少量物品造型细节。**

不推荐先给所有表面叠加统一噪声，也不推荐直接全场景铺设高分辨率贴图。

## 3. 写实 MC 材质方案的参考价值

### 3.1 不只是高清底图

Stratum 官方介绍包含法线、镜面及高度信息，并说明效果需要与支持相应功能的光影配合。应学习材质数据与渲染方式的配合，而不是把分辨率当作真实感的唯一来源。

| 原则 | 在本项目中的含义 |
| --- | --- |
| 结构明确 | 木头有木纹和端面，石材有矿物与孔洞，砖石有接缝 |
| 通道对应 | 同一裂缝同时影响底色、凹凸及遮蔽，而不是几套互不相关的噪声 |
| 反光有别 | 裸金属、漆面、抛光石、布料有不同的粗糙度和反射响应 |
| 尺度合理 | 按 1 block = 1 m 设计木板、砖块、纤维和砂粒尺度 |
| 远近分层 | 远看保留大块结构，近看增加微细节，避免闪烁和重复感 |

### 3.2 不能直接照搬 MC 通道格式

LabPBR 对法线、遮蔽、高度、平滑度及反射信息有特定编码。Three.js 常见 ORM 则用 R、G、B 分别存放 AO、粗糙度和金属度。

以后即使引入外部 MC 材质，也需要明确格式并转换，不能直接把 LabPBR 贴图当作 ORM 使用。使用外部资源前还需核对使用与分发许可；本方案优先参考原理，不默认复制第三方材质资产。

## 4. 几猫参考页面的实现方式

### 4.1 生成一套相关联的材质数据

参考页主要通过 GPU 程序生成表面信息，而非主要依赖外部照片。生成着色器中的 `emit` 输出底色、ORM 和高度，再通过独立步骤由高度生成法线。

定位：参考 HTML 约第 4747 行的生成着色器，以及约第 5453 行的生成、缓存和材质创建逻辑。文件包含压缩后的长行，行号仅用于当前版本定位。

流程：

`材质规则 → 底色 / ORM / 高度 → 高度生成法线 → 缓存贴图 → PBR 材质 → 光照与反射`

优势在于同一个孔洞、裂缝或磨损区域会共同影响多个材质通道，而不是只有底色变化。

### 4.2 每种材料有自己的结构规则

参考页分别处理混凝土、砖、油漆、金属、拉丝金属、锈蚀、木材、布料和绳索等材料。

例如，约第 4858 行开始的混凝土包含大范围色差、模板纹、不同尺度的孔洞、骨料、裂缝、剥落、接缝和污渍，并由这些结构共同决定高度、AO 和粗糙度。

这不是简单的“灰色底图加细噪声”，而是先定义材料结构，再生成细节。

### 4.3 使用痕迹有位置和方向

参考页包含掉漆露底、锈水流痕、墙脚潮湿、局部污渍和水珠等处理，根据朝向、位置及湿润参数改变颜色、粗糙度和法线响应。

应借鉴痕迹与环境的关系，而不是把整个世界做旧。Homecraft 仍应以干净、清晰的材质为主，只在合理位置少量增加使用痕迹。

### 4.4 贴图生成与每帧开销分开

参考页按材质和质量选择生成尺寸，缓存结果，使用 mipmap 和各向异性过滤，不是每帧重新生成全部复杂材质。

程序化生成可以减少外部素材依赖，但生成后的纹理仍占显存，生成过程仍有启动成本，不能视为免费。

### 4.5 反射和后处理是配套，不是替代

参考页有天空环境、室内反射探针、地面积水反射，以及曝光、辉光、雾和调色。

本项目优先学习材质组织、结构生成和低成本反射，不默认复制整套后处理，更不能用辉光掩盖表面缺少细节的问题。

## 5. 当前项目的问题与代码依据

### 5.1 高优先级：材质身份被简化为颜色

依据：`world/build.js:629`、`world/build.js:732`、`world/beach-furnish.js:11`。

- 深色橡木、樱花木和部分原木使用 `paint` 加颜色。
- 安山岩、闪长岩、平滑石和部分砂岩使用 `paint`。
- 部分羊毛、地毯及海滩绳索也使用 `paint`。

细节分类依据纹理名称，而不是原来的方块名称。映射为 `paint` 后，着色器无法自动知道物品原本是木头、石头还是绳索。

**影响：只改木纹算法，许多木制品仍不会获得木纹；只改石材参数，映射为漆面的石头也不会变化。**

建议先建立方块、物品与材质类别的对应清单，区分漆面、裸木、树皮、石材、布料和绳索，同时避免改变原模型主要配色。

### 5.2 已有微细节，但基础结构和分类不足

依据：`engine/world/textures.js:371`、`world/material-detail.js:18`、`world/detail-profiles.js:3`。

基础纹理数组为 16×16 像素纹理，采用像素化放大采样。大理石另有独立的较高分辨率程序化贴图，不能把所有表面都概括为只有 16×16。

超清层已经实现砂纹、木纤维、矿物颗粒、金属拉丝和布料织纹，并根据高度扰动法线。应在此基础上调整，而不是误判为没有细节系统。

主要不足：

- 大理石、普通石头、混凝土和泳池瓷砖共用石材分类及基础粗糙度。
- 铬、黑色金属、不锈钢共用基础参数，皮革和橡胶也被放入同一类。
- 多种细节由噪声叠加，尚未形成完整的、与底色对应的材料结构。

建议拆分差异明显的材料，优先补中尺度结构，再调整微颗粒强度。

### 5.3 增强效果受模式和自发光条件限制

依据：`world/material-detail.js:28`、`world/material-detail.js:96`、`engine/ultra-flag.js:1`。

- 普通模式不安装当前材质增强，需要进入 `?ultra` 模式。
- 当 `vEmissive > 0` 时，关闭细节分类，并将细节金属度设为零。
- 部分木地板、框架和摩天轮构件使用少量自发光补亮，可能因此失去表面细节。

建议区分真正的发光体与用于补亮的普通物品，不能继续把“有自发光就关闭细节”当作统一规则。最终规则通过样板和用户视觉审查确定。

### 5.4 物品环境反射没有统一接入

检查当前 `engine/` 和 `world/` 的入口，没有找到统一设置的 `scene.environment` 或物品材质 `envMap`。这不等于完全没有反射：水面等对象有自己的处理，不能混为一谈。

现成参考：`examples/terry-home/world/stainless.js:76`。展示屋的不锈钢使用启动时生成的 128px 室内环境探针，并调整其贡献，不是每帧捕获场景。

建议先给少量金属或抛光物品提供合理的环境内容，再判断是否扩大覆盖，不为每件家具建立独立实时反射。

### 5.5 已复核：地表分类的参数类型不匹配

依据：`world/terrain-detail.js:12`、`world/detail-profiles.js:20`、`engine/world/voxels.js:64`。

`grid.type()` 返回方块类型对象，但地表分类和海岸判断直接拿它与 `'sand'` 等字符串比较。

| 只读函数复核输入 | 分类结果 |
| --- | --- |
| `{ name: 'sand' }`，暴露于室外 | `[0, 0, 0]` |
| `'sand'`，暴露于室外 | `[255, 0, 0]` |

这使该路径的地表分类和海岸遮罩不能按预期生成。应先修正类型使用，再评估对应地表、风沙和湿润效果；本轮没有修改实现。

### 5.6 部分增强文件尚未接入当前入口

`engine/world/ultra-ground.js:155` 定义了另一套地表增强，但当前入口没有找到对 `createUltraGround` 的调用。依赖文件存在，不等于其中效果已经运行。

后续先整理已有增强路径的职责和实际调用，再决定整合或接入哪条路径，避免重复叠加相似效果。本轮不删除或重写已有文件。

## 6. 推荐实施顺序

以下为阶段规划。用户已授权首轮实施，实际交付范围见第 10 节；全场景逐件精修仍在样板视觉确认后继续。

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| P0：正确接入 | 整理材质映射，修正地表类型，核实增强入口 | 代表物品进入正确分支，遮罩分类可自动验证 |
| P1：代表样板 | 木材、石材、砂地、金属、布料、绳索各选代表物品 | 输出固定视角截图和参数，由用户确认方向 |
| P2：结构补全 | 添加相关联的底色、凹凸、粗糙度、接缝和局部变化 | 不把统一噪声当作全部细节 |
| P3：反射与补光 | 必要物品增加低成本反射，梳理非必要自发光 | 补亮逻辑不意外关闭材质细节 |
| P4：物品细节 | 少量增加连接件、边缘、缝线和合理磨损 | 不破坏方块风格、比例、碰撞和性能预算 |

### 六类样板审查重点

| 材质 | 近看重点 | 应避免的问题 |
| --- | --- | --- |
| 木材 | 木纹方向、板缝、木节、端面区别 | 所有面同向条纹，木板像塑料 |
| 石材 | 矿物、孔洞、砖缝，粗石与抛光石区别 | 石头、大理石和瓷砖只有颜色区别 |
| 砂地 | 分层颗粒、轻微沙纹、湿润过渡 | 颗粒过粗、闪烁、周期纹路过强 |
| 金属 | 表面处理、粗糙度、环境反射 | 所有金属都是镜面，或整体发黑 |
| 布料 | 编织、厚度、接缝、必要褶皱 | 织纹过大，远处摩尔纹明显 |
| 绳索 | 股线方向、扭转、轮廓与连接位置 | 仍然只是米色漆面长条 |

样板经用户确认后再推广到全场景，避免一次修改大量物品后无法定位风格问题。

## 7. 实施范围与性能边界

### 7.1 优先在世界层解决

优先调整 `world/` 的映射、分类、样板和现有材质扩展，参考展示屋已有实现，不立即推翻引擎。

如确需扩展引擎纹理数组、材质通道或统一反射接口，实施前说明必要性、涉及文件、普通模式影响和维护成本，再确定范围。不得顺手重构无关引擎代码或回退用户已有改动。

### 7.2 分开讨论风格与质量档位

- 默认保留 16×16 基础纹理和 MC 轮廓，先用正确映射、材质参数及受控程序化细节提升表现。
- 高分辨率多通道贴图属于可选扩展，会偏离当前内置纹理约定，需要单独明确范围和档位。
- 不默认新增后处理，不全场景开启视差或位移，不给所有物体增加倒角几何。
- 复用纹理数组、共享材质和批处理；开销必须测量，不能假定 PBR 升级没有成本。

### 7.3 项目预算

| 项目 | 约束 |
| --- | --- |
| 常见视角 Draw calls | 不超过 60 |
| 三角形 | 不超过 200,000 |
| 实时灯光 | 最多 2 个，常规灯具写入 `bakes` |
| 阴影 | 仅太阳投影，不给新增灯光开启阴影 |
| 首次加载 | 压缩后小于 500 KB，关注新增资源和代码体积 |
| 运行时 | 不新增每帧对象分配，不更新不可见对象 |
| 移动端 | 保留可用普通模式，验证真实手机体验 |

启动时生成纹理可以减少网络素材，但仍有显存、启动时间和 GPU 成本。反射、多通道采样及复杂片元计算均需评估。

上表预算仅约束普通模式。普通模式不能满足预算时，列出超出项目、影响及取舍，由用户决定；超清模式不设这些开销上限，不需要为满足普通模式预算而削减材质质量。

### 10.2 用户审查入口

预览服务运行时，在当前预览地址后追加：

- `?ultra=1&materials=1`：六类样板总览。
- `?ultra=1&materials=wood`：木材。
- `?ultra=1&materials=stone`：石材与抛光石。
- `?ultra=1&materials=sand`：砂地。
- `?ultra=1&materials=metal`：金属，包含弱自发光对照物。
- `?ultra=1&materials=cloth`：布料。
- `?ultra=1&materials=rope`：绳索，有股线几何样板。
- `?ultra=1`：正常世界的超清材质；不带 `materials` 不显示样板台。
- `?ultra=0`：普通模式。

截图目录：`tools/.check/materials/`。`desktop-sample-overview.png` 和 `phone-sample-overview.png` 为总览，其余文件按设备、模式、区域或材质命名；`report.json` 保存统计及检查结果。
